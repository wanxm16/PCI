# 医药招商与流向库存系统 · Demo（V0.2）

依据《医药招商与流向库存系统_功能需求与Demo设计_V0.2》实现的前端演示：覆盖**招商管理、流向与库存查询分析、任务中心与 AI 经营助手**，14 个规格页面入口加 1 个 AI 经营洞察页。所有页面共用一份关联的模拟数据集，AI 与页面共用同一套指标与规则层。

> 演示范围不含交易处理：没有下单、仓储作业、财务、佣金或结算。

## 快速开始

```bash
cd demo
npm install
npm run dev      # http://localhost:7321
npm test         # vitest，锁定演示主线数字与规则
npm run build    # tsc -b（严格模式）+ vite 构建，产物在 dist/
```

运行单个测试：`npx vitest run --globals -t "<测试名>"`

技术栈：React 18 · TypeScript · Vite 6 · antd 5 · @ant-design/plots · dayjs · react-router 6 · vitest。纯前端 SPA，无后端，"服务层"在浏览器内模拟。

## AI 能力

所有数字来自 `metrics/` 与规则函数，权限由服务层注入，不由模型决定。回答把**数据观察**和**待核实的解释**分开列出。AI 生成的任务、简报都是草稿：任务需用户预览确认后才保存，简报不会自动发送；AI 不会自动审批、确认、变更状态或对外发送。

- **经营分析**：本月变化解释与贡献归因、销售对比、临期批次、库存可售天数、知识问答。
- **销售主管视角**：客户流失风险预警（`RISK_RULES` 评分）、目标达成与缺口（含 Q4 时间进度）、团队对比、个人业绩分析、周会材料。
- **页面内专项诊断**（各页"AI …"页签，结论直接展示）：
  - 招商漏斗：阶段到达与转化、最弱环节、停留超 30 天的卡点机会。
  - 临期去化：到期前按日均消化不完的合格批次 + 近 6 个月买过同品种的候选客户（同省优先）。
  - 授权健康度：即将到期、待确认、生效无推广、暂停仍推广、范围重叠等，给出健康分排序。
  - 流向结果分析：构成 Top5、变化贡献、退货、短效期到货、单价差异与数据质量。
- **经营洞察与提醒**：扫描销售、目标、客户、库存、招商授权、数据质量生成洞察卡；可勾选生成提醒待办（同日同一异动去重）。

示例问题：`解释10月销售变化`、`哪些客户有流失风险`、`10月目标完成情况和缺口`、`分析陈晓的业绩`、`招商漏斗诊断`、`临期库存去化建议`、`授权与推广健康度`、`生成本周销售周会材料`、`生成本月经营简报`。

## 演示主线

1. **销售变化分析**：工作台 →"解释本月变化"→ 9 月 ¥120 万 → 10 月 ¥96 万；杭州滨江仁济医院 −15 万、宁波海曙康宁大药房 −6 万，前两名占降幅 87.5% → 销售对比下钻 → 生成简报与任务草稿 → 任务中心。
2. **临期库存处理**：库存管理 → 临期批次 → 批号 B2511X1（300 盒，11-28 到期，日均 8 盒，25 天约消化 200 盒，预计剩 100 盒）→ AI 去化建议页签查看候选客户 → 生成待办。
3. **招商四页联动**：目录选品 → 新建机会并跟进 → 阶段改为"合作确认" → 自动生成授权**草稿**（不生效）→ 补全并提交 → 模拟通过 → 在授权范围内新建推广并启动 → 记录活动。还可演示：暂停授权后执行中推广同步暂停；到期授权只能续期生成新版本；范围外客户被拦截。
4. **销售主管视角**：AI经营洞察 → 销售业绩页签查看三位负责人 → AI 业绩分析 → 经营简报页签下载周会材料。

## 业务口径（易错点）

- **单位**：数量不跨 SKU、不跨单位（盒/瓶/支）相加，按 SKU 与基本单位分组。
- **库存**：总库存、有效库存、当前库存、可用库存是四个不同指标；不以售价计算库存金额。
- **净销售**：销售为正、退货为负；对比基数 ≤0 时不显示变化率。可售天数 = 可用库存 ÷ 近 30 天日均对外净销售（不含内部调拨），日均 ≤0 时不估算。
- **临期批次**：按（货权主体, SKU, 批号）去重，跨仓同批次计 1 次；30/60/90 天窗口为演示配置。
- **关联**：流向与库存先按 SKU 和范围聚合再关联，避免多对多放大。
- **缺失 / 0 / 未知**是三种状态，缺失不显示为 0。
- **日期区间**：内部半开区间 `[start, end)`，界面显示含端点日期。
- **招商对象各自独立**：确认机会只生成授权草稿；授权分审核状态（草稿/待确认/已通过/已退回/已撤回）与业务状态（未生效/生效中/已暂停/已到期/已终止）；续期和变更生成新版本；单条范围内各维度需同时满足，多条范围取并集，空范围表示"未完成"而非"不限"；推广完成不等于成交；暂停目录品种不撤销授权；商业授权**不会**扩大系统数据权限。
- 每个查询响应都带 `query_id`、`data_as_of`、`metric_version`、`applied_filters`、`permission_scope_summary`；列表、合计、导出与 AI 使用同一查询条件与数据版本。

## 预埋边界案例

基期为 0 的客户（C039）、10 月仅退货客户（C040）、无近期销售品种（SKU-029）、客户别名、同名不同规格/厂家、8 月重复导入 2 条（已去重）、单位转换缺失（SKU-026）、单边调拨与数量差异、上海仓快照时点不同、跨仓同批次、授权范围重叠（AUTH-001/005）、即将到期授权（AUTH-008）、未生效/暂停/到期/待确认授权。

## 测试

`npm test` 锁定以下数字和规则。修改 `src/data/mock.ts` 或规则阈值后必须仍然通过：

- 9 月 ¥120 万 → 10 月 ¥96 万；客户 A −15 万、客户 B −6 万，前两名占降幅 87.5%。
- SKU-X 日均 8 盒，25 天约 200 盒；跨两个仓的同一批次计 1 个；重复导入已去重。
- 流失风险：C040 为高风险，C001/C002 降幅分别为 −15 万/−6 万，C039 不纳入；10 月目标 120 万、实际 96 万；Q4 时间进度 33/92。
- 临期去化：B2511X1 预计剩 100 盒且有候选客户；区域角色看不到上海仓；漏斗到达数单调不增；AUTH-008 因即将到期标为高优先。
- 流向分析：对比期推算规则；10 月销售分析的贡献数字与上面一致。

## 已知限制

- 未接入大模型，只能识别示例问题及其变体；接入后模型密钥应只保存在后端，模型故障时报表与查询需照常可用。
- 权限、幂等键与 `expected_version` 在前端模拟，生产环境需由服务端校验。
- 下载的 Word 简报是 HTML 格式的 `.doc`，部分 Word 版本打开时会提示格式与扩展名不一致，选择继续打开即可。
